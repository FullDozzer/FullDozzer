# ИНК · Расписание

Telegram-бот расписания для всех групп и преподавателей колледжа. Python 3.11+, aiogram 3, aiohttp, SQLite, Pillow.

## Возможности

- 73 группы из `POST /2025/json/groups`; каталог периодически обновляется, а встроенный снимок используется при недоступности сайта.
- Выбор группы с фильтрами по курсу и форме обучения.
- Команды с основным и premium/collectible username: `/help@mellowagent`, `/date@mellowagent 10.11.2026` и другие.
- Расписание на сегодня, завтра и произвольную дату; поиск преподавателя по фамилии.
- Независимые уведомления для выбранной группы и для каждого преподавателя.
- PNG-карточки расписания с ДИНАМИЧЕСКОЙ высотой: холст подгоняется под количество пар, подгруппы внутри пары, длину предметов и строки изменений.
- Единые информационные карточки групп: форма обучения, бюджет/коммерция, база, курс, семестр, даты семестров.
- Топ преподавателей группы по изученным часам — команда `/top` или просто «топ».
- График нагрузки по неделям с выбором периода месяц / 3 месяца / 6 месяцев / год — команда `/graph` или «график».
- Один актуальный экран: при листании кнопками бот правит своё прошлое сообщение.
- Постоянный кэш расписаний и изображений.
- Учёт завершённых пар и прогноз по прежней формуле для каждой группы отдельно.
- Платная неанонимная рассылка с предварительной модерацией.
- Карточка анонса «бот теперь для всего колледжа» — PNG 1080 px в той же палитре, что расписание, и готовая HTML-подпись к ней.

## Кэш

`schedule_cache` хранит владельца (`group:ID` или `staff:ID`), дату, хэш содержимого, нормализованные занятия и путь к PNG.

1. Первый запрос скачивает расписание и создаёт изображение.
2. Повторный запрос читает SQLite и существующий PNG без HTTP и Pillow.
3. Монитор проверяет сегодня и завтра для всех групп, включая ожидающие первой публикации, а также подписанных преподавателей.
4. При изменении хэша старая картинка инвалидируется, данные заменяются, подписчики получают новую версию.
5. При ошибке сайта старая версия не затирается.

Файлы находятся в `DATA_DIR/images`, база — в `DATA_DIR/bot.db`. В Docker `DATA_DIR` должен быть постоянным volume. `MONITOR_CONCURRENCY` ограничивает число одновременных обращений к сайту.

## Учебные часы

При первом выборе группы запускается одноразовый backfill с 1 сентября. Состояние хранится в `study_jobs`, обработанные даты — в `lesson_backfill_days`. Разные группы считаются независимо.

Каждая подгруппа сохраняется со своим предметом. Параллельные подгруппы не удваивают общее время группы. Отменённые занятия не учитываются. Один академический час равен 40 минутам. Формула прогноза не изменена:

```text
X  = фактически завершённые минуты
De = учебные дни с 1 сентября до сегодня
Dr = оставшиеся учебные дни до 30 июня
R  = X × Dr / De
Y  = X + R
```

## Динамическая высота карточки расписания

Ширина картинки фиксирована (1080 px), а высота больше не берётся из лестницы форматов — она считается по фактическому контенту:

1. Масштаб блоков — самый крупный из `SCHEDULE_SCALE_LADDER`, при котором контент ещё влезает в `SCHEDULE_HEIGHT_COMFORT` / `SCHEDULE_HEIGHT_ABS_MAX`.
2. Layout измеряется честно: Pen меряет теми же шрифтами, что и рендер.
3. Высота холста = шапка + все карточки пар + зазоры + подвал + safe area, округлённая по `SCHEDULE_HEIGHT_STEP`.

Поэтому одна пара — компактная карточка, восемь пар — вытянутая, а пара с подгруппами выше обычной (у каждой подгруппы свой блок со своим предметом и аудиторией). Границы: `SCHEDULE_HEIGHT_FLOOR` (пустой день не превращается в полоску) и `SCHEDULE_HEIGHT_ABS_MAX` (защита от «полотенца»). Кропа не бывает никогда.

## Аналитика группы: топ и график

`load_teacher_rankings()` считает изученные часы каждого преподавателя внутри группы. Время — слоты `(дата, пара)`: пара с подгруппами у разных преподавателей даёт каждому своё время подгруппы, но общая сумма группы не удваивается. Короткая запись сайта («Степанов С.В.») и полное ФИО из `staff_directory.py` схлопываются в одного человека. Часы — академические (1 акад. ч = 40 мин).

`load_workload_series()` собирает нагрузку по календарным неделям (с понедельника) за период из `LOAD_CHART_PERIODS`:

| Команда | Период |
| --- | --- |
| `график` / `/graph` | 3 месяца (по умолчанию) |
| `график за месяц` | 1 месяц |
| `график за 3 месяца` | 3 месяца |
| `график за 6 месяцев` / `полгода` | 6 месяцев |
| `график за год` | 12 месяцев |

Под картинкой графика те же периоды доступны кнопками (`load:1m`, `load:3m`, `load:6m`, `load:12m`) — их можно переключать без повторного ввода команды.

## Карточка анонса

Объявление подписчикам рисуется тем же кодом, что и остальные карточки, —
`render_announcement_image()` в `bot.py`. Ширина фиксирована (1080 px), а
высота считается по контенту: пункт с пояснением занимает две строки, без
пояснения — одну, поэтому ничего не обрезается и «…» не появляется.

Текст живёт в одном месте — `ANNOUNCE_FEATURES`, `ANNOUNCE_CALL_BODY` и
`ANNOUNCE_SUBTITLE`. Из него же собирается подпись `announce_caption()`:
картинка и сообщение не могут разойтись. Пункты с пояснением:

| Иконка (Lucide) | Пункт | Пояснение |
| --- | --- | --- |
| `book-open` | Все группы колледжа | 73 группы: любая специальность и курс |
| `id-card` | Информационные карточки групп | форма, бюджет, база, семестры |
| `trophy` | Топ преподавателей группы | по изученным часам — `/top` |
| `chart-column` | График нагрузки | недели за месяц, 3, 6 и 12 месяцев |
| `zap` | Оптимизация рендеринга | — |
| `sparkles` | QoL-улучшения | — |
| `battery-charging` | Мощности в 4 раза больше | — |
| `bell` | Уведомления преподавателям | о новом расписании |

Иконки — только вендоренные SVG Lucide из `assets/icons/`, штрих
перекрашивается в лавандовый акцент; рукописных глифов нет.

```bash
.venv/bin/python scripts/make_sample_announcement.py   # samples/announcement.png + превью 390 px
.venv/bin/python scripts/send_announcement.py          # dry-run: рендер и подпись, без отправки
.venv/bin/python scripts/send_announcement.py --chat @channel   # проверка на одном адресате
```

`scripts/send_announcement.py` не рассылает всем: он отправляет карточку
одному адресату из `--chat`. Массовая отправка идёт через штатную рассылку
(модерация → оплата → доставка подписчикам), см. раздел ниже.

## Редактирование экранов

Бот не плодит дубли: когда пользователь листает кнопками, ответ подменяет прошлый экран на месте. Ничего при этом не удаляется — ни команды пользователя, ни прежние ответы бота, история чата остаётся как есть.

| Ситуация | Что делает бот |
| --- | --- |
| Кнопка, тип ответа совпал (текст → текст, картинка → картинка) | правит прошлое сообщение (`editMessageText` / `editMessageMedia`) |
| Кнопка, тип сменился (текст → график) | отправляет новое сообщение, прошлый экран остаётся |
| Новая команда (`/top`, «график», текст) | отправляет новое сообщение, прошлый экран остаётся |
| Команда пользователя | не удаляется никогда |
| Отправка ответа не удалась | команда видна, её можно повторить |

Почему так: правка уместна при листании кнопками — пользователь смотрит на один и тот же экран, чат не «прыгает»; новая команда, наоборот, должна быть замечена, поэтому появляется внизу как отдельное сообщение.

Для правки бот помнит id своих последних ответов на чат (не больше 8, не дольше `CHAT_HISTORY_TTL`). В группах редактирование не требует прав администратора. Любая ошибка Telegram (нет прав, сообщение старше 48 часов, «message is not modified») только логируется в `debug` и не ломает сценарий: «not modified» считается успехом, а при настоящем отказе уходит новое сообщение.

Настройки:

```dotenv
CHAT_HISTORY_TTL=21600  # сколько секунд помним id своих сообщений для правки
```

Входная точка для новых обработчиков — `deliver(destination, text=…, photo=…, reply_markup=…, edit=…)`: она сама решает, править прошлый экран или отправить новое сообщение. Флаг `edit` выставляет `_deliver_edits(destination)` — true только для callback-ов.

## Рассылка всему колледжу

Цена обычного сообщения — 50 ₽, рекламного — 150 ₽. Порядок:

1. Пользователь принимает правила и отправляет одно сообщение.
2. Выбирает обычную публикацию или рекламу.
3. Модератор видит автора и содержимое, одобряет или отклоняет заявку.
4. Только после одобрения пользователю выставляется счёт Telegram Payments.
5. После проверки валюты, суммы, payload и статуса платежа сообщение копируется пользователям бота с указанием имени и username автора.

Запрещены 18+, насилие, сливы и персональные данные, травля, дискриминация, мошенничество, вредоносные ссылки, спам и незаконная реклама. Анонимной публикации нет.

Для включения нужны:

```dotenv
PAYMENT_PROVIDER_TOKEN=токен_платёжного_провайдера
ADMIN_IDS=123456789,987654321
```

Без этих значений кнопка сообщает, что рассылка недоступна; счета не создаются.

## Premium

Дополнительные usernames для команд перечисляются через запятую без `@`:

```dotenv
BOT_USERNAME_ALIASES=mellowagent
```

Основной username бот получает через `getMe` автоматически. Упоминания других ботов не принимаются.

HTML-заголовки поддерживают `<tg-emoji>`. Укажите ID custom emoji из набора, доступного боту:

```dotenv
PREMIUM_EMOJI_ID=...
```

Если значение пустое, используется обычный строгий текст без декоративных emoji.

## Запуск

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
.venv/bin/python bot.py
```

Или через Docker. Не храните `.env` в Git.

## Проверка

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Тесты используют временную SQLite-базу и не обращаются к боевому токену.
